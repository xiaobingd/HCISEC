# CycleGAN 留出池认证头低成本重训

- 实验 ID：`AUTH-HOLDOUT-20260923`
- 日期：2026-09-23
- 状态：运行中（user2–user9 队列已启动；bo 等待正确模型）
- 目的：在不重新训练 CycleGAN 的前提下，修复认证头直接使用 CycleGAN 训练样本造成的跨阶段泄漏

## 方案与原因

每位用户历史 CycleGAN 均采用 `test_size=0.1`、`val_size=0.1`、`random_state=42`。本实验精确重建该索引，仅将没有参与 CycleGAN 梯度更新的 validation 与 test 合并为认证候选池，再在候选池内部划分认证头训练、模型选择验证和最终测试。

这是成本受限的补救协议，不等同于预先设计的严格外层 holdout。CycleGAN validation 曾用于固定间隔可视化，虽然没有用于梯度更新或自动 best-checkpoint 选择，但仍存在人工观察带来的弱开发集接触风险。因此本实验可用于重新判断趋势和准备 E1，不应表述为最严格的独立泛化结果。

## 数据隔离边界

- CycleGAN 训练集：不得进入认证候选池。
- 认证候选池：各用户 CycleGAN validation + test。
- 认证头训练/验证/测试：在候选池内按固定 seed=42 分层划分，比例约为 60%/20%/20%。
- 只在远程实例保存样本索引清单和文件 SHA-256；GitHub 仅记录聚合数量、代码哈希、模型哈希和结果。
- 不提交原始数据、特征、模型文件、凭据或未脱敏路径。

## user2/user3 重复核查

两个用户的 ACC 文件 SHA-256 不同。逐样本对规范化数组字节计算 SHA-256 后，精确重复样本交集为 `0`。这只能排除完全相同的样本，不能排除高度相似、同源片段或身份标签问题；后续仍需进行近邻相似度和时间来源审计。

### bo 阻塞原因

新实例当前可见的 bo CycleGAN 模型对应旧 `acc1.npy` 150 样本数据，而活动协议以 `acc.npy` 300 样本重建留出索引。二者不能绑定。为防止再次产生错误结果，bo 认证头未启动；需要取得与 300 样本数据绑定的 CycleGAN 最终模型后才能继续。
