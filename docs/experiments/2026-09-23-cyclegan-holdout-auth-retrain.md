# CycleGAN 留出池认证头低成本重训

- 实验 ID：`AUTH-HOLDOUT-20260923`
- 日期：2026-09-23
- 状态：九套认证头训练与验证已完成；协议后续确认过度限制，仅保留为诊断实验
- 目的：在不重新训练 CycleGAN 的前提下，修复认证头直接使用 CycleGAN 训练样本造成的跨阶段泄漏

## 方案与原因

每位用户历史 CycleGAN 均采用 `test_size=0.1`、`val_size=0.1`、`random_state=42`。本实验精确重建该索引，仅将没有参与 CycleGAN 梯度更新的 validation 与 test 合并为认证候选池，再在候选池内部划分认证头训练、模型选择验证和最终测试。

这是成本受限的补救协议，不等同于预先设计的严格外层 holdout。CycleGAN validation 曾用于固定间隔可视化，虽然没有用于梯度更新或自动 best-checkpoint 选择，但仍存在人工观察带来的弱开发集接触风险。因此本实验可用于重新判断趋势和准备 E1，不应表述为最严格的独立泛化结果。

## 数据隔离边界

- CycleGAN 训练集：不得进入认证候选池。
- 认证候选池：各用户 CycleGAN validation + test。
- 认证头训练/验证/测试：在候选池内按固定 seed=42 分层划分，比例约为 60%/20%/20%。
- 只在远程实例保存样本索引清单和文件 SHA-256；GitHub 仅记录聚合数量、代码哈希、模型哈希和结果。
- 不提交原始数据、特征、模型文件、凭据或未脱敏路径。

## user2/user3 重复核查

两个用户的 ACC 文件 SHA-256 不同。逐样本对规范化数组字节计算 SHA-256 后，精确重复样本交集为 `0`。这只能排除完全相同的样本，不能排除高度相似、同源片段或身份标签问题；后续仍需进行近邻相似度和时间来源审计。

### bo 模型找回与遗漏原因

GitHub 历史记录确认 bo 300 样本 CycleGAN 已于2026-09-22完成，模型 SHA-256 为 `77e2c2e1b93bc93a9d8e85e0210e337303e870d7cff98b1b152659a0e75db715`。远程复核得到完全相同的哈希。

先前误判模型缺失的原因是路径解析错误：新实例的 `/root/autodl-fs` 已经映射到文件存储根目录的数据目录，检查时又追加了一层 `/data`，因而搜索了错误位置。按实验记录中的规范路径检查后找回模型。

使用该模型补训 bo 认证头，100 epochs 正常完成；best epoch=85，validation Sep=0.242897，test Intra=0.4237、Inter=0.1790、Sep=0.2447。

## 协议复核更正

新旧 checkpoint 对照确认认证头代码、模型类型和参数配置完全一致。本轮性能下降来自数据协议而非代码变化：旧认证头有1524条训练数据，本轮只有326条；旧评估约28条/人用于注册，本轮只有5–6条/人。

将所有用户同时限制为各自 CycleGAN holdout 是不必要的。对于每套目标用户 CycleGAN，只有目标用户数据需要按该模型的 train/validation/test 边界处理；其他用户从未参与该目标 CycleGAN。认证头也允许使用 CycleGAN train，只要最终认证 test 未进入任何训练即可。

因此当前九套模型及32.07%宏平均 EER保留为“过度限制/小样本”诊断，不作为原认证头结构的最终评价。详细更正见 [E1-H记录](./2026-09-23-e1-holdout-global-vs-personalized.md)。
