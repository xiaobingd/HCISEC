# CycleGAN 逐用户身份认证验证

- 实验 ID：`cyclegan-auth-validation-20260922`
- 日期：2026-09-22
- 状态：已完成
- 用户范围：bo、user2–user9
- 记录原则：只提交汇总指标与脱敏元数据，不提交原始用户数据或特征

## 目的

验证“每个注册用户拥有独立 CycleGAN 模态转换模型和独立认证头”时的身份认证效果，并对每个注册者分别统计认证性能。

## 模型绑定

每个用户的验证运行绑定：

1. 该用户自己的 CycleGAN 生成器检查点；
2. 该用户自己的认证头检查点；
3. 相同的验证协议和数据划分；
4. 一对多身份认证统计。

不同用户之间不复用生成器或认证头参数。验证过程只在远程实例内读取数据，仓库不保存样本、特征数组或模型二进制文件。

## 已记录的步骤

### 1. 建立认证头

- bo、user2–user9 各自完成认证头训练并生成最终模型。
- 九套认证头模型文件均已确认存在。
- 训练结束后没有遗留认证头训练进程。
- 模型文件只保存在远程文件存储盘。

### 2. 启动逐用户验证

验证脚本：远程 `audit_all_users.py`

每个用户使用自己的认证头和自己的 CycleGAN 检查点，输出目录按用户隔离到远程文件存储盘。仓库只接收完成后的汇总结果。

验证协议使用固定 seed=42 的划分；训练/验证/测试样本交集检查均为 0。

### 3. 启动问题与修正

- 首次启动未产生验证结果。
- 原因：后台子进程未继承输出根目录变量，触发未定义变量退出。
- 影响范围：未读取或上传原始用户数据；未形成有效实验结果。
- 修正：停止无效队列，改用固定绝对路径重新启动。
- user2 首次验证还因其 CycleGAN 检查点目录名称不同而失败。
- 原因：user2 使用的是 `samebo200_user2`，不是其他用户使用的 `samebo200safe_user2`。
- 修正：确认专属检查点存在后，仅重跑 user2；最终结果采用重跑结果。

## bo 完整 acc/audio 重跑与加载器修正

CycleGAN 使用 `meiy/1/acc.npy` 与 `meiy/1/audio.npy` 的 300 条完整数据重训，严格 200 epoch。随后发现认证数据加载器的 bo 分支仍固定读取 `./meiy/1/acc2.npy`，导致之前的认证头验证只使用 150 条 bo 数据。

已备份原加载器并将 bo 认证入口改为 `./meiy/1/acc.npy`。修正后元数据核对为 bo=300 条，其他用户路径和样本数未改变；训练/验证/测试交集仍为 0。修正后的认证头和验证均写入独立目录，不覆盖旧结果。

## user2/user3 重复性核查

用户提出 user2 和 user3 可能数据重复，已在远程实例内完成哈希核查：

- 原始文件 SHA-256 不同（仅保留远程核验结果，不提交原始数据）。
- user2 数据形状为 300×80×81，user3 为 297×80×81。
- 逐样本精确哈希交集为 0。
- 两套 CycleGAN 模型 SHA-256 不同。
- 两套认证头 SHA-256 不同。
- 两套验证特征文件 SHA-256 不同，逐元素完全相同比例为 0。
- 对应认证分数向量也不同（最大绝对差异约 1.56，平均绝对差异约 0.66）。

结论：当前证据不支持 user2/user3 原始数据重复，也不支持结果文件复制。两者本轮指标相同，是在相同固定划分下最终分类计数恰好一致；仍建议后续用多个随机种子和独立时间切分复核稳定性。
