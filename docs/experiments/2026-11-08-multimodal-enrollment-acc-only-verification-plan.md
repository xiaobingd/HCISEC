# 同步 Audio–HMD 双模态注册、HMD 单模态验证：实验方案（V1.0）

> 日期：2026-11-08  
> 状态：**P1 E0–E2及E3各完成两种冻结Audio模型的24折探索对照；C系列尚未执行。** [P1结果](2026-11-08-p1-enrollment-results.md) · [E3及阈值诊断](2026-11-08-e3-quality-gating-results.md)
> 补充对照结果：[注册条件阈值](2026-11-08-enrollment-threshold-results.md) · [背景分数归一化](2026-11-08-background-normalization-results.md)
> 仓库：HCISEC  
> 目标：训练阶段未见用户的 **verification（本人/非本人）**，而非九分类 identification。  
> **使用约束：新用户注册时同步采集 Audio + HMD 三轴速度；验证时只使用 HMD 信号，不读取 Audio，也不运行 Audio 教师。**

## 0. 为什么要单独做这个实验

此前的 Audio→ACC 蒸馏主要尝试提高通用 HMD 特征提取能力，但并未让**新用户注册时的 Audio**参与个人模板构建。本方案研究不同的问题：

> 在相同注册发声次数、相同 HMD 查询和相同未见用户划分下，使用新用户的**同步 Audio–HMD 注册对**能否建立更可靠的个体化 HMD 身份模板？其中，Audio 信息和真实同步耦合分别贡献多少？

区别于传统双教师蒸馏：Audio 不仅在离线训练中提供监督，而且在新用户 enrollment 时构建其个人模板；完成注册后，verification 严格 ACC-only。

不得仅因增加双模态融合层就宣称“发现耦合生理特征”。耦合的判别价值、跨词稳定性以及 ACC-only 可利用性都需要负控制和未见用户实验验证。

### 0.1 已有实验提供的起点（不是本方案结果）

- 2026-11-08 严格未见身份 8目标×3种子共24折，跨词原 ACC：TAR 73.96%、FAR 20.14%、HTER 23.09%；ECAPA 均匀 Audio 关系蒸馏 HTER 22.92%；ERes2NetV2 均匀蒸馏 HTER 22.74%，差异很小，不能证明稳定蒸馏收益。
- VibraVox ACC 主干微调仅已发布 bo/seed42 首折：跨词 AUC 由 88.72% 升至 98.09%，但固定阈值 TAR 仅由 33.33% 升至 37.50%。这是新用户分数校准值得研究的线索，不代表新注册机制已验证。
- 原始本地数据约九人×30词×10次，合计2697组有效配对；本轮默认沿用排除 yue 的八用户探索群体，排除本身具有事后选择局限。部分词标签依据采集顺序推断，未逐条完成语义核验。

## 1. 研究问题、假设与可证伪结论

- **RQ1（双模态注册）**：在 K 次相同发声下，额外利用 Audio 能否优于 HMD-only 注册？
  - H1：E2（固定融合）在未见用户上优于 E0（ACC-only），且改善不是增加注册发声次数造成。
- **RQ2（个体化）**：用户级注册质量与跨模态一致性是否支持自动选择 Audio 融合权重？
  - H2：E3（注册质量自适应）优于 E2，并改善困难用户而不损害最差用户 FAR。
- **RQ3（同步耦合）**：同一次发声的 Audio–HMD 时间/频率关联能否提供超出“两个身份 Embedding 简单融合”的可迁移信息？
  - H3：C2（真实同步耦合）优于同容量 C1；在同人同词错配、时间错位控制 C3/C4 下优势减弱。
- **RQ4（认证可用性）**：上述收益是否能转化为固定阈值下的 TAR 提高和 FAR 控制，而不仅是 AUC 改善？
  - H4：在内层预先选择的安全工作点，双模态注册具有可复现的未见用户验证收益。

上述均为**实验假设，不是已证实的创新点**。不成立时如实报告负结果。

## 2. 任务定义和严格系统边界

一个合法用户 u 的 K 次**同步注册**：

$$D_u^{enroll}=\{(a_i^u,b_i^u,\mathrm{pair\_id}_i)\}_{i=1}^{K}$$

- Audio 输入 a：来自注册时语音麦克风。
- HMD 输入 b：同次录制的三轴速度（历史代码分支名 ACC）。
- 离线预训练可使用公共及本地 Base 身份的配对 Audio/HMD。
- **新用户注册时**可以读其 K 个 Audio、K 个 HMD 与对应时间戳，**不能**读取其最终 ACC 查询或最终 Audio。
- **验证时**只允许当前 HMD 输入 $b_q$、已固定的 HMD 编码器 $E_B$、只读的用户模板 $p_u$ 和注册之前确定的判定规则；不得再访问 Audio、融合教师或目标测试标签。

统一为：

$$z_q=\operatorname{norm}(E_B(b_q)),\quad s(q,u)=\cos(z_q,p_u),\quad \mathrm{accept}\iff s(q,u)\geq\tau.$$

所有注册方法的 $p_u$ 必须位于 **HMD 查询可比较的身份空间**。Audio/HMD 特征维数相同不自动意味着可以直接比较，需在 Base 身份上学习映射。

## 3. P0 数据、时间同步和隔离审计（所有实验前的门槛）

2. 核验 Audio/HMD 同一次发声的配对关系、时间轴、采样率、同步偏移和缺失段。跨谱/相干分析**必须使用原始或相位有效的时间序列**，不能用旧 80×80 幅值谱冒充同步时域证据。
3. 区分原始速度、时间戳求导估计加速度、VibraVox 真实加速度；每组预处理固定并在 Base 数据上拟合归一化统计。任何外层最终目标/攻击者不能参与全局统计拟合。
4. 核验 30 词标签与重复索引。当前词 ID 部分由顺序推断；关键同词/跨词结论发布前必须核查原始清单，无法核实的条目单独标注或退出正式分析。
5. 写出并自动断言 Base/开发/校准/最终目标/攻击者身份不相交，以及注册和测试 sample_id 不相交。比较 E0–E3、C0–C4 时保持完全相同的查询和 K 条同步发声。
6. GitHub 只记录脱敏协议、脚本、聚合统计和必要模型/输入 SHA-256；不提交原始录音、逐样本特征、私人路径、可逆身份向量或权重。

## 4. P1 冻结编码器的最小可行注册对照：E0–E2

**原则：先冻结全部主干，仅训练 Base 上的轻量 Audio→HMD 映射；不把编码器变化混入注册收益。**

### 4.1 编码器与映射

- Audio：优先对照 VibraVox Audio ECAPA 与 ERes2NetV2；各自版本/权重哈希固定，模型替换不与注册策略选择混合。
- HMD：主实验使用同一个严格 Base-only ResNet18（10–300Hz 速度谱）检查点；VibraVox ACC 主干作为独立复现实验，需记录其前端是时间戳速度求导 + 三轴分别编码并汇总。
- 输出身份向量 $z_A=\operatorname{norm}(E_A(a))$、$z_B=\operatorname{norm}(E_B(b))$。
- 映射 $M_\theta(z_A)$ 输出 HMD 身份空间；只用 Base fit 身份的配对数据训练。默认采用小 MLP（如 192→128→192），L2 归一化、权重衰减和开发集早停。
- 映射损失以**跨文本身份一致性**为主：同人异词正对、异人同词困难负对；可辅以正确配对余弦和 Base 身份 SupCon。不得仅凭逐样本 L2 对齐损失下降认定身份迁移有效。
- 超参数（映射深度、loss 权重、融合系数）只能在 Base 身份内部模拟未见用户的开发任务中选，不得使用 Cal/Target/Attacker 的最终分数。

### 4.2 注册方法

设：

$$p_B=\operatorname{norm}\left(\frac{1}{K}\sum_i z_{B,i}\right),\quad p_A=\operatorname{norm}\left(\frac{1}{K}\sum_i z_{A,i}\right),$$

$$p_{A\to B}=\operatorname{norm}(M_\theta(p_A)).$$

|编号|注册信息|模板|科学问题|
|---|---|---|---|
|**E0**|K 次 HMD|$p_B$|标准单模态注册|
|**E1**|同 K 次 Audio|$p_{A\to B}$|Audio 是否可独立建立 HMD 验证模板|
|**E2**|同 K 次同步 Audio+HMD|$\operatorname{norm}((1-\lambda)p_B+\lambda p_{A\to B})$|Audio 是否提供独立注册增益|
|**E3**|同 E2|由注册质量估计 $\lambda_u$ 的融合模板|个体化可靠性是否增加收益|

E2 的 $\lambda\in\{0,0.1,0.25,0.5,0.75,1\}$；仅内部 Base 开发选择，测试用户统一使用已锁定策略。**不得在未见目标最终测试后，为每个目标挑选最优 $\lambda$。**

E1/E2 的映射是通用 Base 模型，外层目标用户 Audio 只参与其本人注册模板，不用于梯度更新、教师微调或全局阈值选择。

**主裁决**：E2 vs E0，在同一折同一种子、同一 K、同一 ACC 查询下比较。E1 提供可解释的 Audio-only 注册下界/上界参考，不能代替 E0。

## 5. P2 注册质量自适应：E3

在 E2 可能有效后再研究 E3。令：

$$\lambda_u=g_\phi(Q_A(u),Q_B(u),Q_{AB}(u)), \quad p_u=\operatorname{norm}((1-\lambda_u)p_B+\lambda_u p_{A\to B}).$$

注册质量指标仅取自 K 条注册录制，例如：

- 同人跨重复 Audio 原型一致性和 HMD 原型一致性；
- 映射后两个注册原型的一致性；
- 注册振动信噪、有效发声时长、缺失轴/截断比例（仅可通过设备可观测信号计算）；
- 在 Base 开发身份上预估的稳定性，不读取最终用户的正确/错误查询统计。

$g_\phi$ 初期用正则化线性/浅层网络、限制输出在 [0,1]，或先用预先固定的显式质量公式；不应以少数 Base 用户训练容量很大的元学习网络。

**必要对照**：固定 $\lambda$、随机同分布 $\lambda$、只基于 HMD 质量估计的 $\lambda$、E3 三模态质量信息融合。确保 E3 有效性不只是更多可训练参数的结果。

如 E2 未优于 E0，应先诊断映射和身份尺度，不强行继续 E3。

## 6. P3 真正同步耦合的独立贡献：C0–C4

“两个 Embedding 拼接”或“同一次发声特征匹配”本身**不能证明**学习了生理耦合身份规律。需要与普通融合相区分的同步对照。

### 6.1 耦合证据候选

从同一注册 pair 的原始 Audio 与每个 HMD 速度轴（或明确标记的估计加速度）计算：

- 时间对齐后的互相关峰值、延迟及不同词重复的稳定性；
- 声学/速度能量包络对应；
- 预先确定频带内的互谱、幅值平方相干性；
- 可选的跨时序表示或轻量交互头，但不得把网络 attention 权重直接解释为物理因果耦合。

从 Audio 身份向量、HMD 身份向量和耦合特征得到注册端条件向量 $c_u$。该向量**仅在注册时计算**。

### 6.2 模板生成器

令 $F_\phi$ 在 Base 用户上通过 episodic verification 学会“从 K 次注册得到能匹配未来 HMD 查询的身份模板”：

$$\Delta_u=F_\phi(\{z_{A,i},z_{B,i},c_i\}_{i=1}^{K}),\qquad p_u=\operatorname{norm}(p_B+\rho\,\Delta_u).$$

$\rho$ 和残差范数上限事先在开发折选择；训练时使用同人**未进入注册支持集**的 HMD 录制作为 query，并采用同人/异人对比或二元验证损失。正式外层验证时不更新 $F_\phi$、$E_B$、阈值或目标用户模板参数。

### 6.3 必做消融与负控制

|编号|注册侧做法|目的|
|---|---|---|
|**C0**|E2，固定权重普通双模态融合|基线|
|**C1**|同等容量模板生成器，输入 Audio/HMD 身份向量，无同步时序特征|控制模型容量与普通融合|
|**C2**|C1 + **真实同步**相干/时延/交互特征|目标：同步耦合的额外身份价值|
|**C3**|保持相同用户、相同单词，将 Audio 与 HMD **不同重复错配**再提取耦合特征|保留用户/词信息、破坏逐次同步关系|
|**C4**|保持原始身份、词和样本，预定义时间错位/相位扰动后提取耦合特征|检验真实时间对齐是否关键|

控制 C3/C4 需要尽可能保持每模态独立特征的输入集合和数量不变；仅改变耦合特征的正确对应。另报告不加入同步特征的 matched-capacity 对照，防止把容量或错误对照引起的输入破坏误判为耦合收益。

**裁决逻辑**：C2 > C1 且 C3/C4 系统性减弱收益，才更支持“同步身份耦合提供独立信息”；否则只能主张一般双模态注册融合有效（前提是 E2>E0）。

**重要限制**：测试时没有 Audio，不能现场计算 Audio–HMD 互谱或其他耦合量；耦合特征只能通过注册端 $p_u$ 转化为 HMD-only 可验证信息。若必须拿测试 Audio 才有效，该方法不满足部署目标。

## 7. P4 严格未见用户：与已有 HCISEC 协议衔接

### 7.1 外层八用户探索协议

先复用已冻结的 8 用户环形划分，3 种子 42/43/44 共24折：

|角色|人数|能否用于模型/阈值|
|---|---:|---|
|Base|4|可训练编码器（若做独立主干实验）、映射 M、注册模板网络 F；内部开发选超参|
|Calibration|2|只用于外层注册-验证阈值校准；不训练任何通用模型、融合或质量权重|
|Target|1|仅 K 条**同步** Audio/HMD 注册；最终 ACC 本人查询|
|Unseen attacker|1|仅最终 ACC 攻击查询；不参与训练与校准|

每折预先固定用户划分；严格防止 E0/E1/E2/E3 的 M/F、归一化、开发选择访问外层目标或未见攻击者。为公平比较，使用**相同的 ACC 主干检查点、相同的注册原始样本和相同查询**。

同时报告 all-seven attacker 来源：它混合训练/校准已见身份，**不可全部称为未见攻击者**。

当前八人排除 yue 为探索性选择，结果不能代称完整九人泛化。下一阶段应单独完成 yue 标签、佩戴、跨词数据审计并预注册包括 yue 的验证，避免按测试效果删除困难用户。

### 7.2 同词/跨词匹配对照（主实验 K=12）

沿用历史 final 六词：Down、Up、Zoom、Record、Play、Reset。每人每词取共同前8次录制，两组三词轮换方向：

- 查询词组 $W_q$：固定三个词各后4次，合计12条 ACC 查询；两种条件查询集合**完全一致**。
- 同词注册：$W_q$ 三词各前4次，同步 Audio/HMD，共12次发声。
- 跨词注册：另一组 $W_e$ 三词各前4次，同步 Audio/HMD，共12次发声。
- 两种条件在每个方向采用相同编码器、相同查询、相同注册发声次数，且同一方法共享一个仅来自 Calibration 身份的阈值。
- 两方向合计每目标24条 genuine 查询、24条严格未见攻击者查询；all-seven 每目标168条攻击查询。0/24 攻击接受**不等于真实 FAR 为0**。

这里同词/跨词只改变**注册词集合**，而不是重新训练不同模型。词语标注尚需核验，此限制须在每次结果中披露。

### 7.3 K-shot 和配对录制一致性

推荐预先固定 $K\in\{1,3,5,12\}$；每个 K 10 组注册抽样种子（或明确保存全部可行组合）。在所有 E/C 方法上使用完全相同 K 条发声，Audio 与 HMD 由**同次发声同步获取**；不能将双模态注册说成采集了 2K 次发声。

K 小于12时，抽样可用相同支持集并尽量覆盖不同词；报告 K 的抽样变异，但不能将10个抽样种子当作10个独立用户。

### 7.4 阈值与校准防泄漏

- **各注册方法**可以在相同独立 Calibration 身份、相同拟真注册与攻击协议上独立求一个阈值；不可生搬硬套 ACC-only 的数值阈值，因为分数分布可能变化。
- 每种方法的阈值策略（例如校准 EER、固定开发 FAR=5%）必须在实验开始前选定；同词/跨词共享其方法阈值；最终目标和攻击者所有测试分数一律不用于调整。
- 如研究合法用户注册时的质量自适应，所需质量统计只能使用合法注册样本，并在 Base 开发身份上学习参数；不能根据目标最终 ROC、TAR/FAR 调阈值。
- 两名 Calibration 身份对 1% FAR 尾部估计不足；5% FAR 也需如实报告校准/最终偏移。必要时增加独立采集身份或重复折的身份级稳健性分析，禁止声称满足某安全保证。
- 同时报告**描述性 AUC/EER**与**冻结阈值** FAR/FRR/TAR；不能将测试集最佳阈值当成部署性能。

### 7.5 统计口径

主要终点：crossword、严格未见 target-vs-unseen attacker、K=12、冻结阈值下的 **macro HTER 与 FAR/TAR**；配套 AUC、EER、worst-target FAR、worst-target TAR。

先按用户聚合，后按3训练种子汇总。报告每目标×种子的配对差值（E2−E0、E3−E2、C2−C1）及用户级不确定性；仅八人，避免把共享录制的配对数量当作独立样本量。再报告 all-seven、sameword、K-shot 敏感性和阈值迁移误差。

额外记录：推理延迟、注册发声次数、模板持久存储大小、是否真正验证时不使用 Audio。

## 8. 公共数据预训练与跨域迁移

- 初期 E0–E2 可以在当前严格 Base-only 编码器及缓存上开展低开销验证。
- E3/C 系列的可训练注册网络可能因每折只有4名 Base 说话人而严重过拟合：优先在 **VibraVox 说话人互斥划分**上训练/验证通用注册任务，再只用本地 Base 身份有限适配；公共预训练、迁移及主干选择需另设 matched 对照。
- VibraVox 为额头单轴物理加速度，本地为三轴速度；任何从本地速度导出的“加速度”必须标明是估计导数，且不能默认采样率/频率响应可直接对齐。
- 公共预训练的完整句子与本地单词时长不同，应检查有效频带、时长裁剪、用户/文本捷径。仅使用两模态身份 Embedding 的实验不等价于证明真实同步耦合。
- 最终系统只能有 HMD 推理链；注册阶段可以缓存 Audio 编码结果及由同步对计算的模板，需为模板保护和用户撤销预留机制。

## 10. 预注册成功/失败判据与论文定位

1. **E2 > E0**，且同一冻结安全策略下真实测试 FAR 没有明显恶化，才支持双模态注册提供额外认证价值。
2. **E3 > E2** 才支持基于注册可靠性的个体化融合有效。
3. **C2 > C1** 且 **C3/C4 降低 C2 优势**，才有较强证据支持真实同步耦合信息具有独立可用价值。
4. 若仅 AUC 改善、TAR 在固定阈值下仍很低，不得声称实用身份认证已成功；必须检查校准用户到新用户的分数偏移。
5. 若改进只存在于 Base 已见身份、某个目标或某一随机种子，不得推广到未见用户。
6. 若 E2/E3/C2 未超过简单 ACC-only，则报告负结果，不要按最终测试调权重、删困难攻击来源或重新定义指标。

推荐论文中的问题划分（待实验验证）：

- **研究点一**：VR HMD 信号的跨模态身份表征学习/增强。
- **研究点二**：**同步 Audio–HMD 个体化注册与 HMD-only 验证**，强调注册侧的信息利用、可迁移模板与冻结阈值下的认证，而非“再堆一个 Audio 教师”。

这两者技术目标不同，但是否能构成独立创新还取决于现有相关工作核查与独立消融增益。

**本轮立即行动**：冻结现有主干，审计目标 Audio 注册池可合法提取的 Embedding；优先执行 E0/E1/E2 的同折同查询对照。只有此最小问题获得证据，再研究个体化 E3 和真实同步耦合 C 系列。
