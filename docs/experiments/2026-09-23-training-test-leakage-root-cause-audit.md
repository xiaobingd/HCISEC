# 训练—测试泄漏根因审计

- 日期：2026-09-23
- 范围：CycleGAN、认证头、E1-A/E1-B 评估链路
- 状态：已定位
- 审计方式：仅检查代码、日志摘要、样本索引和聚合计数；未读取或提交原始样本内容

## 结论

训练脚本并非完全没有划分数据。CycleGAN 和认证头都各自进行了训练/验证/测试划分。错误发生在跨阶段：各阶段重新随机划分，没有共享不可变的外层训练/留出索引；bo 数据从150条改为300条后，又只重训了 bo 认证头，导致旧认证头与新评估划分不一致。

因此 E1 的最终测试样本大量进入过 CycleGAN 训练，user2–user9 的 E1 测试样本还大量进入过旧认证头训练。

## 各阶段实际行为

### CycleGAN

- 每个用户使用自己的 ACC/Audio 数据。
- 配置为 test_size=0.1、val_size=0.1、random_state=42。
- 实际约80%训练、10%验证、10%测试。
- 梯度更新只使用 CycleGAN 训练集；验证集用于训练过程中的可视化/检查。

### 认证头

旧认证头日志显示：

- bo 使用150条；
- 九用户合计2541条；
- 划分为训练1524、验证508、测试509；
- 配置等价于60%训练、20%验证、20%测试。

修正 bo 后的新 bo 认证头日志显示：

- bo 使用300条；
- 九用户合计2691条；
- 划分为训练1614、验证538、测试539。

认证头优化器只使用 train loader，模型选择使用 validation loader，test loader 在训练结束后评估。

### E1 评估

E1 加载修正后的2691条数据，重新按 seed=42 划分为：

- train=1614；
- validation=538；
- test=539。

E1 随后再将 validation 分成注册模板和阈值校准部分。

## 错误一：CycleGAN 与认证评估没有共享外层索引

CycleGAN 对每位用户独立按80%/10%/10%划分；认证评估对九用户合并数据按60%/20%/20%重新分层划分。两套随机过程不等价。

| user3 | 60 | 49 |
| user4 | 59 | 48 |
| user5 | 60 | 45 |
| user6 | 60 | 46 |
| user7 | 60 | 53 |
| user8 | 60 | 46 |
| user9 | 60 | 50 |
| 合计 | 539 | 432 |

约80.1%的E1最终测试样本已经参与对应CycleGAN的梯度训练。

## 错误二：bo数据规模改变后只重训了bo认证头

user2–user9 的认证头训练日志均显示使用旧数据规模2541条，其中bo为150条。E1评估改为2691条，其中bo为300条。由于分层随机划分在数据规模变化后重新生成，其他用户的局部训练/测试索引也发生变化。

| 目标用户 | E1测试样本 | 进入旧认证头训练 |
|---|---:|---:|
| user2 | 60 | 36 |
| user3 | 60 | 32 |
| user4 | 59 | 30 |
| user5 | 60 | 34 |
| user6 | 60 | 39 |
| user7 | 60 | 41 |
| user8 | 60 | 36 |
| user9 | 60 | 40 |
| 合计 | 479 | 288 |

约60.1%的 user2–user9 E1 目标用户测试样本进入过对应旧认证头训练集。

bo 的新认证头是在2691条数据条件下重训的，其认证头划分与E1第一层划分一致；但 bo 的 E1 测试样本仍有51/60进入过bo CycleGAN训练。

## 错误三：完整性检查范围不足

audit_all_users.py 检查的是评估脚本新生成的 train/validation/test 三组之间是否重复。该检查得到0，只能证明新划分内部没有重复。

它没有检查：

- E1 test 与 CycleGAN 实际训练索引的交集；
- E1 test 与认证头历史训练索引的交集；
- 数据规模或顺序改变后，旧模型训练索引是否仍与新评估索引一致。

因此之前“交集为0，所以没有污染”的解释不成立。

## data.py 中的直接证据

活动版本的 load_real_auth_data() 明确：

- bo 读取完整 acc.npy；
- 注释写明“移除原本剔除训练集的拆分逻辑，直接使用 bo_all”；
- user2–user9 也读取全部 acc.npy；
- 之后由认证头或评估脚本各自重新划分。

文件中保留的旧注释函数曾尝试只取 bo 的 CycleGAN val+test，但：

- 只处理 bo，没有处理其他用户；
- 使用20% test和20% validation，而实际 CycleGAN 配置是10%和10%；
- 因此也不能恢复正确的跨阶段留出集。

## 正确修复

必须生成一次不可变的外层索引清单，并让所有阶段读取它：

1. 对每位用户的 ACC/Audio 配对样本先划分 outer_train 与 outer_holdout；
2. CycleGAN 只读取 outer_train，并在其中划分训练/开发验证；
3. 认证头只读取 outer_train，并在其中划分训练/模型选择验证；
4. outer_holdout 再划分 enrollment、threshold_calibration、final_test；
5. E1-A/E1-B 只能使用 outer_holdout 的三个子集；
6. 保存每个用户的索引、样本哈希、划分版本和模型绑定；
7. 在最终评估前强制断言 final_test 与 CycleGAN/认证头训练索引交集为0。

## 影响

E1-A、E1-B 和基于它们形成的用户难度结论保留为探索性结果，不作为独立泛化证据。所有正式指标需要在统一外层划分下重新训练九套 CycleGAN、九套认证头并重新评估。
