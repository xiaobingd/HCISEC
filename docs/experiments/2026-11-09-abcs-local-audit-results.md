# ABCS 本地语料与内容协议核查

## 实际数据状态

已读取用户提供的本地目录。此报告是数据核查，尚非认证结果。

最终 ZIP 分卷的中央目录含 47,346 个 WAV、101 位说话人。本地已解压 20,058 个 WAV，其中 42 位说话人的文件集合与归档目录完整对应；缺少前一 .z01 分卷，不能声称已获得完整数据集。完整集合对应不等于全量 CRC 通过。

真实转写解析得到 47,344 条记录。两行只有录音 ID 而没有可用文本，不能纳入严格内容划分。部分转写 ID 含额外段号，已修正解析；段号不能当成重复录制编号。转写同一序号在不同用户间可能存在措辞差异，因此必须按实际文本匹配。

作者 README 描述为 100 人、47,182 组；此处统计来自当前发布文件目录，不将两种口径混用。来源：https://github.com/wangmou21/abcs 。

## 已验证的候选子集

只按真实文本覆盖选择候选，不使用认证成绩挑人。现有音频中找到 8 人共有的 125 条规范化文本，对应 1,000 个双通道原始 WAV。

- 1,000 个文件逐一通过归档大小、CRC 与音频解码核查。
- 全部为 16 kHz、双通道、16 bit PCM，总时长约 55 分钟。
- 这 1,000 条中未发现完全相同的 PCM 载荷副本。
- 文本来自官方转写，尚未完成抽样听辨或独立 ASR 语义核验。

已比较两通道 2–7 kHz 与 50–2000 Hz 能量比，中位数分别约 0.00737 和 0.000796。通道频谱确实存在差别，但这只能提供诊断证据，不能单独据此确认 AC/BC 顺序。当前仍保持 channel0/channel1 标记，未生成带确定模态标签的训练清单。

## 同内容与跨内容的边界

1. 支持候选“异人同句攻击对照”：同一查询文本有来自八人的不同原始录音。
2. 暂不支持八人匹配的“同人同句独立重复训练/测试”：候选搜索未找到八人共同满足每句至少两次独立录制的文本。全量转写搜索亦未找到这种覆盖，但搜索并非所有用户子集的穷举，不将其表述为整个语料绝对无重复。
3. 支持准备“跨句闭集”协议：八个身份参与训练，真实句子组全局隔离。相同句子的所有身份及所有派生窗口必须留在同一角色。跨句不等同于词汇、音素完全不重叠。

不能将一条录音切窗或增强成多条来补足同句独立重复数。不能把相同数字后缀当作相同内容。认证阈值、教师特征及用户群选择不得参考最终查询/攻击结果。

## 下一步门禁

先确认通道语义并抽样核对转写，再锁定跨句划分和同句攻击查询。补齐分卷后可扩大身份覆盖，但不能预设下载完整就会新增同句重复。保持所有人相同预处理；只用训练身份/训练内容选择共享频带、标准化参数与辅助损失权重。

对照保持相同 BC 编码器、预算与认证后端，比较 BC-only 和 T3（身份损失 + 共享谱辅助 + 包络辅助）。T3 频带应由 ABCS 训练数据测量，不能直接复制 ESMB 的候选频带。此次尚未开始模型训练，未产生 FAR/TAR。
